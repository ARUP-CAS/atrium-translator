## Context

The code side of this issue is **done**. `c24f5bc` ("edits pre-production + replace-append switcher")
shipped the `replace|append` switch and the two defects the first pass uncovered, and all eight CI
workflows are green on that HEAD.

That changes what this plan is for. It was written to schedule an experiment in replace-only mode and
defer the design question; it now schedules an experiment that can **show reviewers both output shapes
from the same input**, which is the only way the question was ever going to be answered honestly.

What is left is no longer engineering:

- **No release carries the feature.** The tag `v1.0.0-beta` is **9 commits** behind `test`, the version
  string has not moved, and the changelog has no row for the switch. The beta's own image tags were
  never published (the Trivy fixable-CRITICAL gate failed on both matrix targets and promotion is
  `if: success()`), so there is still nothing to pull by name.
- **The live-backend lane has never been dispatched** — 0 `workflow_dispatch` runs, on a job whose own
  header says to run it before a release.
- **The experiment has not been run**, and the hub runbook's translator row is still five empty boxes.

One loose end is genuinely ours: `tests/test_output_mode.py` was untracked when the commit was made and
never landed. Everything else on this page needs a person, not a patch.

## Execution Plan

### Phase A — What is left of readiness

**A1. Add the missing test file.** `tests/test_output_mode.py` covers `normalize_output_mode`, append
semantics, attribute copying, idempotency, ALTO label-not-duplicate, and both fallback-counter paths.
Without it the suite runs **573** tests at **84.39%** instead of **592** at 85.38%. Both clear the
`fail_under = 81` floor, which is precisely why its absence is silent — and why it will stay silent
until someone changes the switch and nothing catches it.

**A2. Re-cut the release — now the top blocker.** Tag from current `test`, bump the version in
`para_config.txt` and `CITATION.cff`, and add the changelog row for the switch. Then **verify the tags
actually landed**: a green workflow run is not the evidence, the presence of `:1.0.0-beta.N` / `:latest`
in the registry is. The previous attempt went green on `release.yml` (the bundle) while the image
promotion never fired, which is exactly how this was missed the first time. Also reconsider the
GitHub `prerelease: false` flag, which currently presents a beta as the repo's latest stable release.

**A3. Dispatch the `live-backend` lane.** One click. Its own header says to run it before a release, and
the beta was cut without it. It is the only check that the real CUBBITT contract still matches what the
stub asserts.

**A4. Let append answer the XSD question.**

```bash
python main.py ./data_samples/my_documents --xpaths amcr-fields.txt \
    --source_lang cs --output-mode append \
    --xsd https://api.aiscr.cz/schema/amcr/2.2/amcr.xsd
```

A validation failure **is the answer** to whether `maxOccurs` permits the repeated element — not a bug
in the feature. If it fails, the English moves (an attribute, a wrapper, or the Document JSON only) and
the switch's plumbing is unaffected.

**A5. Decide the run's licence posture.** Pass `--source_lang cs` explicitly rather than relying on
`config.txt`'s `source_lang = auto`. Auto-detect loads FastText, which `para_config.txt` marks
`conditional` and **CC BY-NC 4.0**, inherited by every output. On a Czech-only corpus the detector buys
nothing. The LINDAT backend still contributes CC BY-NC-SA 4.0; tell the institutes what licence their
outputs carry before the run, not after.

### Phase B — Hand over

**B1. Resolve the recipient.** See Open questions — K4TEL's call, and it changes the corpus.

**B2. Package what the institutes need.** The hub already has all three pieces: `docs/k8s_deployment.md`,
`docs/templates/k8s/atrium-service.deployment.yaml`, and `docs/k8s_acceptance_runbook.md`, whose
translator smoke request is already specified as
`curl -s -X POST localhost:8000/translate -F "file=@<large.alto.xml>"` — *"the slowest request shape in
the fleet"*.

**B3. Respect the governance boundary.** Per `atrium-project/agent_dev_logs/plans/40.plan.md:10-11`,
**GitHub Actions must not be wired to any ARÚP/ARÚB environment**; the boundary is a Docker image built
and run entirely inside their own environment. This cannot be driven from CI or from a development
session. It is a genuine handover.

**B4. State the known limits up front.** `docs/k8s_deployment.md`'s "Known limits" already warns that
translator handles requests synchronously inside the HTTP cycle and that a request outliving the grace
period is cut. Given the call-count spread, flag `GRACEFUL_SHUTDOWN_S=20` (with
`terminationGracePeriodSeconds`) as the first dial to raise for large ALTO, and `MAX_UPLOAD_MB=50` second.

**B5. Say which mode to run.** The default is `replace`, so an untouched deployment behaves exactly as
before. Ask for **both**: the same corpus once per mode, which is what makes Phase D answerable.

### Phase C — Run it

Follow the hub runbook's shared procedure: apply the manifest, wait for the startup probe, confirm the
probe contract from inside the cluster, then send real traffic and trigger a rolling restart mid-flight
to confirm nothing in flight fails. Fill in **translator's row** in the Results log.

Worth saying in the handover note: **this same run closes hub
[#55](https://github.com/ufal/atrium-project/issues/55)'s external acceptance criterion for
translator** — the one hub #53 records as *"not ours to close"*. One deployment advances three issues.

Run both corpora if the recipient question resolves to "both": AMCR metadata exercises the append path
and the 10 XPaths in `amcr-fields.txt`; ALTO exercises the token realignment and the geometry question.
They fail in different ways and only the first is cheap to fix.

### Phase D — Collect feedback that answers the question

The switch changes what can be asked. Reviewers no longer have to imagine the alternative — show them
the same record twice:

1. **Which artifact would you rather receive?** Hand over one record in each mode. This is the whole
   question, in the only form that produces a defensible answer.
2. **Is unlabelled English acceptable?** In replace mode `<amcr:okres xml:lang="cs">` sits two elements
   from an `<amcr:nazev>` that now holds English and declares nothing. Can a harvester live with that?
3. **Does the appended shape validate on your side?** A4 answers it against the XSD; this asks whether
   their own tooling accepts it.
4. **Does the ALTO geometry matter to you?** 224 blanked and 304 over-filled `String` boxes of 7229,
   none resized. If they render or search on coordinates, replace-mode ALTO is not usable — and that
   confirms the parallel-artifact reading from their side rather than ours.
5. **Should controlled-vocabulary fields be resolved from the thesaurus?** The 23 `HES-`/`ruian-` element
   types are still untouched. That is a lookup, not a translation, and the pairs are already harvested.
6. **Throughput and failure modes** — wall-clock per document, anything that timed out or came back
   empty, and what the new fallback summary lines say.

Record the answers under `agent_dev_logs/` and return the completed Results-log table, per the runbook.

### Phase E — Decide and hand off

With feedback in hand, take the decision on the issue thread. Because the switch already exists,
"adopt append" is now a **default change plus a changelog note**, not a project. Whatever remains —
thesaurus lookup for controlled fields, or relocating the English if the XSD refuses the repeat —
belongs to a follow-up issue. #46 closes when the run has happened, the feedback is recorded, and the
decision is written down.
